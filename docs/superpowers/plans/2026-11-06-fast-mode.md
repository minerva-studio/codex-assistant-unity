# Fast Mode Implementation Plan

**Goal:** Add a functional Codex-style Fast switch to the model popup using advertised service tiers.

**Architecture:** Workspace owns the tier override; effective speed derives from it and the model's catalog default. The client forwards tier ids through thread/start, thread/settings/update and turn/start. The popup footer observes workspace state and does not persist a second boolean.

- [x] Parse serviceTiers/defaultServiceTier and derive Fast capability from advertised fast/priority ids.
- [x] Sync config, resume and notifications; send explicit default when Fast is off. Update sticky settings for queued turns and include speed on explicit turns, independently of reasoning effort.
- [x] Add a rounded speed card and capsule switch below the searchable model list, with usage description and disabled unsupported state.
- [x] Run focused state/UI checks and inspect protocol requests without generating a conversation response. Compile in the existing Editor and inspect the real popup.
- [x] Update remaining-work documentation and commit locally without push/merge.

Evidence: CLI 0.166 bindings expose serviceTiers/defaultServiceTier and config/thread serviceTier fields. The live catalog advertises Fast with id priority. Official speed documentation: https://learn.chatgpt.com/docs/agent-configuration/speed
